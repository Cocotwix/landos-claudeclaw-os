# LandOS governed module map

| Area | Canonical modules | Governed responsibility |
|---|---|---|
| Operator projection | `src/landos/routes.ts`, `deal-card-projection.ts`, `deal-card-canonical.ts` | Assemble accepted state for the visible Deal Card. |
| Property evidence | `property-research-store.ts`, `property-intelligence-store.ts`, `parcel-identity.ts` | Persist accepted property-scoped evidence behind identity guards. |
| Hermes boundary | `hermes-landportal-auto.ts`, `hermes-landportal-import.ts` | Launch fixed sibling work and deterministically admit exact-subject categories. |
| Markets and comps | `market-matrix-store.ts`, `market-pulse.ts`, `market-research.ts`, `comp-providers.ts` | Keep market panels, sold comps, and active competition explicit and sourced. |
| Browser work | `browser-session.ts`, `browser-intelligence.ts`, `landportal-browser.ts` | Operate approved browser surfaces without cross-property or cross-tab contamination. |
| Documents and visuals | `document-registry.ts`, `visual-capture-workflow.ts`, `visual-intelligence.ts` | Preserve artifact identity, source, and association. |
| Knowledge retrieval | `rag-knowledge.ts`, `knowledge-store.ts` | Retrieve contextual documents without becoming canonical business state. |
| Runtime and memory | `scripts/runtime/landos-runtime.mjs`, `scripts/memory/landos-memory.mjs` | Managed lifecycle, health, checkpoint replacement, and audit. |

When canonical state and localhost disagree, trace persistence, API projection,
client transformation, and rendered DOM in that order. Never accept a backend
record as a substitute for the missing visible result.
