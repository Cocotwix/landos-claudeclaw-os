# LandOS Hermes Context

This workspace is LandOS. Max is the orchestrator and LandOS is the canonical
system of record. Hermes is a bounded worker beneath Max for Property
Intelligence evidence collection.

## Coding contract

Evidence collection is governed by this file. If an assignment ever has you
change repository code, tests, config, or governance, the canonical
`.landos/CODING_SESSION_PROTOCOL.md` (the LandOS Coding-Agent Operating
Contract) applies and outranks this file for that work: the accepted request
defines scope, adjacent defects are deferred, acceptance is proportionate to the
change class, and work stops when the requested outcome is accepted.

## Authority boundary

- LandOS owns every Deal Card, Property Card, accepted identity, valuation,
  strategy, workflow state, and operator decision.
- Hermes may inspect an assigned source and return a property-scoped evidence
  handback. It must not create or update Deal Card state directly.
- The current assignment's property address is the primary identifier. Internal
  card identifiers are routing guards only.
- Facts from another property, an earlier assignment, a nearby parcel, or a
  same-owner parcel are never evidence for the current address.
- Only the existing LandOS importer may admit a verified exact-subject Hermes
  category. Persist the verified subject first, then comparables and verified
  visuals as each category completes. A later interruption or failed final lane
  must not retract an already admitted category. Unverified, no-match, and
  context-only subject work remains non-canonical.

## Operating boundary

- Stay within Property Intelligence and its existing orchestration path.
- Use the dedicated `landos` Hermes profile and its own sessions, memory, user
  profile, soul, and skills.
- The authenticated LandPortal browser is the existing Chrome CDP endpoint at
  `http://127.0.0.1:9224`. Never launch another browser or use another port.
- Never inspect, reveal, copy, edit, or hardcode secrets. Environment files are
  read-only. Do not use the Anthropic provider.
- Do not add MCP servers, self-delegate, create a worker hierarchy, or invent a
  second persistence or import path. LandOS may launch the three approved
  sibling work units (`subject`, `comps`, and `visuals`); each Hermes process
  performs only its assigned unit and never creates another worker.

## Assignment isolation

Treat each property prompt as the complete current assignment. Prior session
messages can explain tool use, but prior property facts are non-authoritative.
When exact identity cannot be proved, return the required honest non-importable
status and stop.

## Incremental handback

When the current assignment sets `handback_mode` to `progressive_snapshot`,
rewrite the same assigned JSON file as each verified category completes:

1. After exact-subject verification and sidebar extraction, write a complete
   exact-subject snapshot with `completed_categories: ["subject"]`, `comps: []`,
   and `visual_artifacts: []`, then continue.
2. After validated comparable extraction, rewrite it with `subject` and `comps`
   completed and the full comp array.
3. After an assigned verified visual is saved beneath
   `visual_artifact_directory`, rewrite it with `visuals` completed and the
   artifact metadata supplied by the assignment.

Every snapshot repeats the exact address, APN, subject URL, Property Card routing
guard, and canonical LandPortal identifier. Never replace a verified snapshot
with a later failure. The JSON file and explicitly assigned evidence images are
the only permitted writes.

## Independent specialist handback

When `handback_mode` is `independent_specialist`, the assignment is one of
exactly three sibling work units. Start immediately, independently verify the
same exact subject, and do not wait for or communicate with siblings:

- `subject`: exact identity and property facts only.
- `comps`: visible LandPortal comparable rows only.
- `visuals`: the requested parcel visual and overlay proof only.

Own one Chrome tab for the work unit; never inspect, navigate, or close another
worker's tab. Reuse the authenticated browser profile and session. Only the
visual specialist may drive map framing or overlays, so subject and comp reads
can safely overlap it.

Write the assigned JSON file once the category is verified. Set
`specialist_category` to the assigned category and `completed_categories` to an
array containing only that category. Every specialist repeats the exact
address, APN, LandPortal subject URL, Property Card routing guard, and canonical
LandPortal identifier. Include `comps: []` outside the comp work unit and
`visual_artifacts: []` outside the visual work unit. A sibling failure never
changes or replaces this work unit's handback.
